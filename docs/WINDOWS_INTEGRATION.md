# Windows 集成说明

截译把工作台能力拆成三个轻量出口：截图翻译覆盖原选区、选中文本翻译贴在光标旁、桌面/文件夹右键菜单直接开始。主程序仍负责 OCR、翻译和设置，浮层只负责显示结果，不获得文件系统或通用 IPC 权限。

![选中文本翻译小窗](assets/screenlingo-selection-panel.png)

## 三种入口

| 入口 | 操作 | 结果位置 |
| --- | --- | --- |
| 全局快捷键 | `Alt+Shift+S` 框选截图 | 译文浮层覆盖截图选区 |
| 全局快捷键 | `Alt+Shift+X` 读取当前选中文本 | 光标旁的小窗 |
| 全局快捷键 | `Alt+Shift+T` 翻译剪贴板 | 光标旁的小窗 |
| 系统托盘右键 | “截屏翻译”“翻译选中文本”“翻译剪贴板” | 同上 |
| 资源管理器右键 | 桌面或文件夹空白处“截译 · 截屏翻译”“截译 · 翻译剪贴板” | 截图浮层或小窗 |

点击浮层里的“复制译文”即可复制；“打开工作台”会把完整原文、译文和截图提问入口带回主窗口。浮层关闭后不会因为后台请求晚到而重新弹出。

## 右键菜单的真实边界

Windows 没有提供“让任意普通应用把自己的项目插入所有软件原生右键菜单”的公开接口。要在记事本、浏览器、IDE 的文本菜单里增加项目，通常需要每个应用自己的插件机制、原生 Shell 扩展或进程注入；最后一种会破坏轻量和安全边界，本项目不采用。

因此当前实现是：

- 在 Windows 资源管理器的**桌面空白处**和**文件夹空白处**注册每用户右键菜单。
- 在**系统托盘右键菜单**提供“翻译选中文本”，与全局快捷键共用同一套 Windows UI Automation 读取逻辑。
- Windows 11 会把经典 Shell 菜单收进“显示更多选项”；这是系统行为，不是截译额外增加的一层。
- 选中文本读取只使用 Windows UI Automation 的 `TextPattern`，不模拟 `Ctrl+C`，也不会改写剪贴板。密码框会被拒绝读取；不暴露 `TextPattern` 的应用会显示提示，并提供“翻译剪贴板”作为退路。

## 注册表与卸载

开启“Windows 桌面右键菜单”后，截译只写入当前用户（`HKCU`）的以下位置，不需要管理员权限：

```text
HKCU\Software\Classes\DesktopBackground\shell\ScreenLingoScreenshot
HKCU\Software\Classes\DesktopBackground\shell\ScreenLingoClipboard
HKCU\Software\Classes\Directory\Background\shell\ScreenLingoScreenshot
HKCU\Software\Classes\Directory\Background\shell\ScreenLingoClipboard
```

关闭设置中的开关会删除这些键。程序不会写入 `HKLM`、不会注册服务、不会添加开机启动项，也不会修改文件关联。便携版移动位置后，重新启动一次截译即可把菜单命令更新到新路径。

## 浮层窗口

- 无边框、置顶、不进入任务栏；截图结果窗口按选区 DIP 坐标定位。
- 小窗在光标旁出现，靠近屏幕边缘时自动翻转，并随内容高度调整，最大高度有限。
- 浮层使用独立的预加载脚本，只暴露状态读取、复制、关闭、打开工作台、翻译剪贴板回退和调整高度这几个动作；截图图片不会发送给浮层。
- 按 `Esc` 或右上角关闭按钮可关闭；浮层被点击后才会取得键盘焦点，避免选中文本翻译时抢走当前应用的输入焦点。

## 已知限制

- “翻译选中文本”依赖目标应用向 UI Automation 暴露选区。Electron、Chromium、记事本和多数现代编辑器通常支持；部分自绘控件、旧式应用或管理员权限窗口可能不支持。
- 右键菜单只覆盖资源管理器，不覆盖任意应用内部的文本菜单，原因见上。
- 便携版直接删除程序前，建议先在设置中关闭右键菜单；否则 Windows 会暂时保留指向已删除路径的菜单项。
- 多显示器混合缩放、管理员权限程序、远程桌面下的窗口定位仍需在真实桌面上逐项验收。
