# 截译移动版：把屏幕里的文字变成可操作的内容

> 产品方案与官方能力调研，2026-09-27；首版实现范围更新于 2026-09-28。Android 0.1.0-alpha.1 已同步到仓库并提供个人体验包，构建与测试状态以交付记录为准，不代表已经完成真机验收。需求强度与性能目标仍待真实用户验证。

## 产品判断

移动端有类似需求，但首要问题不再只是“看懂代码报错”，而是“在另一个 App 里看到一段难以理解、无法复制或不好选择的内容，希望只处理其中一部分，然后继续原来的事情”。

截译移动版的定位是一个轻量的**截图和文字处理工具**：分享一张截图或一段文字，识别后按句、按词选择，直接翻译、解释、复制或查找。第一版先做 Android，保留以后接入 iOS 的数据和交互模型。

竞争优势需要验证：不是增加一个翻译输入框，而是减少“截图 → 打开翻译 App → 导入 → 整页翻译 → 找到真正需要的一句”的来回操作。系统已经能顺畅完成的纯复制与整段翻译，不应要求用户再换一个工具。

## 借鉴什么

用户提到的小米传送门与锤子大爆炸，提供了两条有价值的产品思路：从当前内容快速抵达下一步操作，以及把难选择的文本拆成可选择的片段。这里将它们作为用户指定的交互参考，不对其私有实现、识别模型、权限方式、历史版本功能或用户规模作未经核实的断言。本次没有取得足以验证这些技术细节的一手资料。

| 参考方向 | 截译要保留的体验 | 移动首版的落地方式 |
| --- | --- | --- |
| 从内容直达动作 | 看到内容之后，马上获得合适的下一步 | 选择内容后显示“翻译、解释、复制、查找”，减少菜单层级 |
| 把文字拆开选择 | 可以只拿走一个词、一句话或几段不相邻的内容 | 本地 OCR 后提供按句与按词选择，保留原文顺序 |
| 随手可用 | 尽量留在用户刚才的任务上下文 | Android 分享面板与支持的文字选择菜单作为入口，完成后可返回原 App |

普通第三方 App 的系统权限与手机厂商不同。首版不承诺“任意 App 内全局长按即可唤起”，也不通过无障碍服务、常驻录屏或后台监听剪贴板来模拟系统级能力。

## 谁会在什么时候用

以下是待验证的需求假设，优先级依据与现有 ScreenLingo 的连续性、发生频率预期和实现边界制定，并非已完成用户访谈的结论。

| 优先级 | 场景与人群 | 当前可能的困难 | 成功结果 |
| --- | --- | --- | --- |
| P0 | 用手机看 GitHub、开发群、远程终端的开发者与学习者 | 报错常以截图出现；希望理解错误，而非翻译整页聊天 | 分享截图，只选报错；保留 `TypeError`、路径和命令，再得到中文翻译或解释 |
| P0 | 看外语社区、邮件、商品说明的普通用户 | 页面不可复制、选择柄难拖动，整屏翻译掩盖关键内容 | 只选择需要的一句话；翻译后立即回原 App |
| P1 | 看课程、技术文章截图的学习者 | 想复制术语、整理两三句话，需要反复切 App | 点选不相邻片段，按原始顺序复制或查找 |
| P1 | 收到图片式地址、订单、行程的用户 | 需要其中一个字段，不需要翻译整张图片 | 提取并复制选中的字段；首版查找仍由用户主动触发 |
| P2 | 菜单、路牌、整页 PDF、长截图重排 | 需要相机、复杂版面、更多语言或多页流程 | 等前面的高频路径得到验证后再扩展 |

## 第一版范围

第一版以 Android 8.0 及以上系统的“分享 → 提取 → 选择 → 使用”闭环为准，采用 Kotlin 与 Jetpack Compose，不引入账号体系、社区或云端历史记录。

### 入口

1. **分享截图或文字**：接收单张图片或 `text/plain`，进入处理页；仅有链接时显示可编辑的链接文字，不自动抓取整篇网页。
2. **选中文字 → 截译**：注册 `ACTION_PROCESS_TEXT`。只有提供兼容文字选择菜单的宿主 App 才可能显示，入口位置也由系统与宿主决定；不能保证微信、浏览器和所有自绘控件都出现。
3. **打开 App → 选择图片 / 粘贴文字**：系统图片选择器只授予选中图片的访问；粘贴由用户点击，不在启动或后台自动读取剪贴板。

系统截图本身仍由用户惯用的截图手势完成。首版不申请悬浮窗、录屏、通知或无障碍权限作为必需前提。

### 提取与选择

- 图片使用随包 ML Kit 模型在本机 OCR，首版覆盖英文与中文；识字无需首次联网下载模型。给出识别中、取消、没有文字、图片读取失败等明确状态。
- 默认按词点选，提供“按句”切换。中文分词或断句不准确时允许编辑原文；首版没有拖拽选词或独立的按字符选择模式。
- 原图与识别文字可相互对照。保留代码标识符、文件路径、URL、版本号、换行和标点，不为展示词块而破坏原文。
- 支持全选、清空、手工编辑和多片段选择。动作执行前展示实际选中文字；多片段按原文顺序拼接，不按点击顺序拼接。
- 普通翻译与文字提问只发送选定文本。提问对话框提供默认关闭的“附上当前截图”，用户主动勾选后才把导入图片与问题一起交给配置的看图模型；即使没有选中文字，也可以只附当前截图提问。界面告知会发送整张图片。原图不写入应用历史记录，也不删除用户原图。
- 文本上限为 10,000 个字符、最多 600 个选择片段；问题上限 2,000 个字符。图片会缩小处理，大图、长图与复杂排版建议先裁出所需部分。

### 五个动作

| 动作 | 行为 | 网络与前提 |
| --- | --- | --- |
| 翻译 | 默认译成中文，显示结果，长按可选择和复制 | 文字模型留空时使用必应在线翻译，无需密钥；配置文字模型后改用该模型。两者均只发送选中文字 |
| 提问 | 面向报错、缩写、术语，回答“什么意思、可能原因、下一步如何确认”；可主动附图 | 需要用户配置兼容的文字模型或看图模型；不自动执行修复命令，回答应由用户核实 |
| 复制 | 复制当前选择，显示完成反馈 | 完全本地 |
| 分享 | 把选中文字交给系统分享面板 | 接收方由用户选择；是否联网取决于接收应用 |
| 查找 | 把选中文字交给手机的搜索应用，没有可接收的搜索应用时打开必应网页搜索 | 用户点击时才执行；查询文字会交给对应搜索服务 |

服务未配置时，识别、选择、编辑、复制与必应在线翻译可用；AI 提问提供明确的模型配置入口，不显示伪造结果。必应采用网页翻译接口，可能因页面变化、验证或限额而不可用；配置模型后不会静默切回必应。截图问答已经纳入首版，但需用户单独填写支持图片输入的模型并在每次提问时主动勾选附图。

### 屏幕结构

```text
系统分享 / 文字选择菜单 / 主页面
                  ↓
            内容处理工作台
       原图预览或可编辑原文
         [按词] [按句] [全选]
           可点选的文字片段
        已选内容预览与片段数
    [翻译] [提问] [复制] [分享] [查找]
                  ↓
         工作台内显示结果
          长按结果选择和复制
```

主页面只放“选择图片、粘贴文字”和简短入口说明；设置中再放服务地址、模型与密钥。接口、权限、打包等开发说明不进入普通用户主流程。

触摸目标至少 48 dp，选中状态同时使用文字或勾选反馈，支持系统字体放大、深色模式和读屏。识别及网络请求应可取消；重试沿用当前选择，不要求用户从分享重新开始。

## Android 与 iOS 的真实边界

| 能力 | Android | iOS | 产品决定 |
| --- | --- | --- | --- |
| 从别的 App 接收截图、文字 | `ACTION_SEND`，取决于来源 App 分享的类型与授权 [1] | 分享面板中的扩展接收宿主提供的内容；翻译这类内容处理更适合 Action Extension [7][8] | 首要跨 App 入口，不能读取宿主未分享的数据 |
| 出现在文字选择菜单 | API 23 起提供 `ACTION_PROCESS_TEXT`，宿主支持情况不同 [2] | 不承诺像 Android 一样把任意第三方动作加进所有 App 的选择菜单 | Android 做增强入口，始终保留分享和粘贴 |
| 选择已有截图 | Photo Picker；不可用时 AndroidX 可回退 `ACTION_OPEN_DOCUMENT` [3] | Photos picker 提供选中资源，不需要整库访问授权 [9] | 只访问用户主动选择的图片 |
| 本地 OCR | ML Kit Text Recognition v2 有随包模型和动态下载模型两条路径 [6] | Vision 文字识别在设备上执行 [10] | Android 首版使用随包中英文模型，避免首次识别依赖 Google Play Services 下载 |
| 直接读取别的 App 屏幕 | MediaProjection 需要用户同意；Android 14 起每次会话授权、令牌一次性，且涉及前台服务 [4] | 首版不提供常驻跨 App 截屏能力 | Android 后续可评估用户主动触发的单次截屏；不把后台无感截屏作为承诺 |
| 后台监听复制内容 | Android 10 起通常只有当前有焦点的 App 或默认输入法可以访问剪贴板 [5] | 首版只设计用户主动粘贴 | 不依赖常驻剪贴板监控 |
| 用无障碍服务获取其他 App 内容 | 技术可见性受宿主影响；非无障碍工具还涉及醒目披露、同意和 Google Play 声明审核 [11] | 不作为本产品方案 | 首版不申请，避免将普通翻译包装成无障碍用途 |

iOS 可以复用“导入 → 识别 → 选择 → 动作”的产品模型，但需单独实现平台入口与 Vision 适配。Apple 的 Share Extension 文档以发布和分享内容为主要用途；本产品应优先验证 **Action Extension**，其接收内容也由宿主决定。原生 iOS 构建、签名和真机验证还需要 macOS/Xcode 与适用的 Apple 开发者分发配置，Windows 代码工作区本身不能证明 iOS 已可发布。

## 网络、隐私与国内设备

- **无代理**：使用设备当前网络访问必应或所配置的模型服务；连接失败时保留原文与选择，提供可理解的错误与重试。
- **已开启手机系统 VPN 或代理**：客户端采用系统代理配置，通过 Android 网络栈使用当前可用路由；VPN 的分流规则由系统与 VPN 应用决定。直连、VPN 和 Wi-Fi HTTP 代理仍需分别真机验证，不能只凭“已开启代理”承诺所有请求都走代理。
- Windows 的 `v2rayN.exe` 不是手机能力。移动版不扫描 PC 本地端口，不读取节点、订阅，也不替用户开关 VPN。用户明确配置的网络策略不得被静默绕过。
- 首次离线状态也应能完成图片导入、本地 OCR、文字选择与复制。完全离线翻译需评估语言模型下载大小、设备内存、延迟和质量，不等同于 OCR 离线。
- ML Kit 的[官方条款和隐私说明](https://developers.google.com/ml-kit/terms)区分识别内容与诊断指标：输入及识别结果在设备处理，但 SDK 会发送性能/使用指标，也可能检查更新与兼容性。首版在设置和用户说明中披露，不能宣传为“完全无网络通信”或将 SDK 模型声称为 MIT 开源。
- 普通翻译仅发送选中文字给必应或自定义模型；文字提问发送问题与选中文字给自定义模型。只有主动勾选附图时发送图片。结果仅在本次会话保留；“稍后再看”若后续加入，应让用户主动保存和删除。
- 密钥通过 Android Keystore 加密保存在本机，应用备份关闭；不设置明文降级存储。不保存截图、原文和结果历史。配置中的 `localhost` / `127.0.0.1` 指手机自身，不能直接连接电脑上的本地模型；远程服务须提供 HTTPS 地址。

## 验证需求，而非先做大量功能

先邀请 5–8 位经常接触截图英文或不可复制内容的用户，用自己的真实任务对比当前习惯与截译。在获得同意后观察操作，不默认收集个人截图和原文。建议让每人连续 3 天记录出现此类需求的次数与当前做法。

以下是**验收目标假设，不是已测结果**：

| 问题 | 测量方法 | 首轮目标 |
| --- | --- | --- |
| 是否真的减少操作 | 同一任务对比现有方式，从发现内容计时到复制/看懂结果 | 完成时间中位数减少至少 30%；否则重新检查分享入口价值 |
| 用户能否自己找到入口 | 首次使用只提供一行“截图后分享到截译”提示 | 至少 80% 的受试者不经口头帮助完成 |
| 选择文字是否比拖选择柄好用 | 单句、长报错、多片段三个任务，记录误选与撤销 | 80% 的任务不需改用手工粘贴补救 |
| OCR 是否足以支撑动作 | 在不同字号与深浅主题的授权样例上核对关键术语和代码标识符 | 关键字段正确率达 95%；普通正文与代码分开统计 |
| 是否会再次使用 | 3 天后访谈与自愿任务日记 | 至少半数受试者在没有提醒时再次使用；小样本结果仅用于方向判断 |
| 离线与代理是否符合承诺 | 无网络、直连、系统 VPN、Wi-Fi 代理、超时各跑同一流程 | 离线仍可 OCR/复制；网络失败不丢失当前内容 |

性能基线应记录设备、系统版本、图片尺寸、冷/热启动及 OCR 模型。可先把 1080p 截图热 OCR 的中位数 2 秒、P95 5 秒作为待测目标；大图应缩放或提示限制，不通过卡死或无界等待换取识别成功。

## 演进顺序

1. **Android 首版验收**：已编写分享、文字选择菜单、图片选择与粘贴入口，以及本地 OCR、词句点选、复制分享、在线翻译与可选截图提问。接下来完成真机上的无 GMS、常见国产系统、授权入口、离线识字与网络配置验证。
2. **降低唤起成本**：根据实际使用频率，再评估桌面快捷入口、快捷设置磁贴、主动发起的单次截屏；每项都保留系统授权，不默认加入悬浮球常驻。
3. **增强内容理解**：用户主动保存的片段、术语词典、长截图分段，以及截图提问的质量与成本反馈。离线翻译需先验证模型与低内存设备体验。
4. **iOS 产品化**：Photos picker + Vision + Action Extension；沿用选择与动作逻辑，独立验证扩展生命周期、内存限制和返回原 App 的体验。

进入下一阶段的条件是首版已证明减少操作，并且核心使用场景有重复使用；不是把桌面版所有设置与悬浮形态照搬到手机。
